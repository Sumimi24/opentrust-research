OpenTrust: Reliable Model Analysis and RTL Repair with Executable Evidence

模型生成了一个答案，再找另一个模型审核，是否就足够可靠？我们把“答案正确”“审核放行”和“独立测试通过”分开测量，研究不同模型配对的盲点，并在开源硬件任务上检验修复闭环。

01 / THE QUESTION

审核“说对了”，
与工程“做对了”是两件事。

OpenTrust 最早研究生产者与验证者的互信：生产者自身容易犯什么错，验证者是否恰好看不见这些错？前期的成本与证书研究进一步指出，资格目标、数据复用和查询规则都会改变费用。

本轮把主线放在高正确率与低错误放行上。我们不把模型之间的同意当作真值，也不预设跨家族一定更好，而是用明确规则和独立测试追踪每次放行。

Q1

同一个审核模型，面对不同生产者是否一样可靠？

对同一批答案做全交叉审核，分开估计生产错误率 p 和配对漏检率 φ。

Q2

知道配对信息，能否改善质量与覆盖率？

仅用校准集选择审核路线，再在冻结的测试场景比较固定、随机与按生产者选择的路线。

Q3

模型能否在真实工程骨架上修复功能问题？

开放相同上游依赖，限定三次模型调用，先开发测试再独立验证。

证据范围：文本线提供可控的协议分析机制证据；RTL 线提供模块级工程案例。两条线独立报告，不能把文本审核优势直接推广成真实硬件正确性保证。

02 / METHOD & CONTRACT

先定判据，再让模型回答。

1

建立可闭合的任务

将事件顺序、状态更新、容量限制与结束条件写为合同。两个 CPU 判定器分别以在线状态和历史重建方式计算答案，先检查合法样例与缺陷样例。

2

隔离选择与评价

文本按规格 seed 划分校准／测试，同规格的两条轨迹与全部模型配对保持同组。RTL 先冻结选定源码，再运行新的独立种子。

3

同时评价质量与采纳

分别统计精确答案正确率、漏检率、放行率、放行后错误率。接口错误、截断和不可解析输出保留，不悄悄重试后改写为成功。

p = 错误答案 / 全部答案

生产模型的错误率。

φ = 错误且放行 / 错误答案

特定生产—审核配对的漏检率。

risk = 错误且放行 / 放行答案

采纳结果中实际有多少错误。

p × φ 是无条件错误放行概率，不能直接代替放行后的条件风险。全拒绝会降低覆盖率；零次观测错误也不能证明部署风险为零。

03 / LARGE PROTOCOL STUDY

把配对盲点变成可以数出来的结果。

三个自定义工程协议：请求与确认、事务提交、资源与租约。模型判断一条轨迹是否合法；若不合法，必须指出最早错误事件及规则。审核模型检查这份分析是否正确，而不是简单判断轨迹是否合法。

请求与确认

提交 → 接受 → 分块数据 → 完成。检查 ID、序号、累计字节、并发容量与期限。

事务提交

开始 → 写入／参与者准备 → 提交或中止。检查并发事务、准备集合和结束后行为。

资源与租约

申请 → 使用／续约 → 释放或过期。检查容量、租约期限、复用与时间边界。

生产答案的精确正确率

必须同时答对合法性、最早事件编号、错误规则。分母包括接口和格式失败。

05 / OPEN-SOURCE ENGINEERING
从分析协议，走到开源 RTL 的修复闭环。
工程线采用三个固定子系统合同。先确认开源核心与包装参考能运行，再验证注入缺陷确实产生功能错误。所有路线获得相同上游依赖；模型看见待修复包装，看不见正确包装与独立测试反馈。

06 / HOW THE RESEARCH EVOLVED
前期研究没有丢掉，
它决定了本轮要测什么。
概念与文献
区分生产错误与配对盲点
把生产者自身错误率 p、验证者对其错误的漏检率 φ 和决策费用分开。联合生产与验证、顺序认证、缓存和风险控制已有研究，不能仅以系统名称宣称创新。
成本与资格目标
核查“便宜”到底来自哪里
前期冻结池研究发现，改变资格目标和避免不合格候选上的查询会改变费用；结果可能与简单启发式持平。历史数据复用节省新增查询，也不等于减少已发生的总费用。
组合 RTL 实验
生成—执行—反馈—再验证
在位宽转换 FIFO、整包锁定仲裁和可停顿算术流水线上完成过独立测试与预算对照。它们与本轮复杂子系统分别报告。
复杂子系统与判据修订
难度提高，也暴露了测试合同问题
DMA、UDP 与缓存引入多阶段时序。修正过超合同刺激、错误后保持规则和排空计时起点；保留旧记录，重新资格检查和评分。
本轮扩大实验
既测配对机制，也测工程落地
用 120 个独立文本规格场景测配对审核，用开源骨架修复检验工程流程。质量与错误采纳优先，费用和规模口径透明。
文献线：已有工作 → 学到的经验 → 我们如何参考
下列内容直接展示。参考的是研究问题、评测规范与证据边界，代码和网站独立组织。
相关研究及本项目的参照方式
文献／项目已有工作本研究的参照与边界


Learn then Test ↗将候选选择与统计风险控制连接，通过假设检验筛选配置。认证要有明确风险目标、样本单位和多重选择处理；本轮描述性区间不冒充认证。


VerilogEval ↗以可执行测试评价规格到 RTL 的生成，区分编译与仿真错误。冻结工具链，记录截断、编译、超时和功能失败；仿真通过的范围必须写清。


RTLLM ↗设计描述、参考 RTL、测试台，以及语法、功能与综合质量评价。合同与测试台须一致，原始生成与多轮修复成功率分开；本轮未测综合质量。


RTL-Repair ↗利用语义与失败轨迹进行 RTL 修复。生成—测试—修复和反例反馈本身已有先行工作。我们待验证的是模型配对与采纳行为。


SWE-bench ↗真实仓库任务，结合失败转通过与原有测试保持通过。缺陷必须原版失败、参考通过；修复不能只消除一个失败而破坏其他行为。


CVDP ↗硬件工程评测，建议先检查 golden reference 与 harness。先验证测试环境与参考答案，采用机械执行评分；不用模型主观意见作为标签。





07 / CLAIMS & LIMITATIONS
研究贡献写到证据够得到的地方。
已经形成的工作
  • 把生产错误、配对漏检与采纳风险接到同一条可追溯数据链。
  • 构建明确合同、双 CPU 真值与规格分组测试的文本协议评测。
  • 搭建开源 RTL 的参考资格、缺陷资格、有限修复和独立评价闭环。
  • 保留负结果、接口失败、判据修订和费用口径，提供复现材料。
尚不能主张的结论
  • 不能从三个协议族或三个 RTL 合同推出全部工程场景普适有效。
  • 不能说跨家族审核一定优于同家族，或详细反例一定带来收益。
  • 不能把更高预算的多审核路线当作同成本优势。
  • 不能把“没有观测到错误”说成已证明 95% 部署准确率。
创新性定位：本轮提供具体任务、数据接口、配对机制检验和工程证据组织。统计风险控制、代码修复循环和跨模型协作已有研究；新的稳定方法优势须由独立比较支持。
下一步
外部有效性
加入公开标准协议的明确子集与真实历史 RTL 缺陷；保持角色、版本和合法策略固定。
工程规格族
扩展位宽、突发、准入规则和缓存参数，区分新参数、未见规则与新项目外推。
独立认证
若进行正式风险声明，预定样本量、采纳目标和多重选择方式，并采用有效的认证程序。
